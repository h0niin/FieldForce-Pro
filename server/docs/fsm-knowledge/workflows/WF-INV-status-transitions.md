# WF-INV-status-transitions — Invoice Status Transitions

## Overview
Documents every status transition available on the Invoice Detail page and the exact button labels presented for each source status.

## Prerequisites
- User must be authenticated (PrivateRoute guard).
- User must NOT have a Technician role (TechnicianGuard blocks `/invoices`).
- The user must have permission to reach `/invoices/{id}` (sidebar entry requires `invoices:read`).
- There is NO separate permission guard around the status-transition card or its buttons in the code — any authenticated non-technician user who can view the detail page can trigger a transition.
- The status transition card renders ONLY when `availableTransitions.length > 0`. It is hidden when the invoice is in **Paid** or **Void** status (both have empty transition arrays).

## Status Flow Reference

| Current Status   | Available Transition Buttons                              |
|------------------|-----------------------------------------------------------|
| `draft`          | **Sent**, **Void**                                        |
| `sent`           | **Viewed**, **Void**                                      |
| `viewed`         | **Partially Paid**, **Paid**, **Overdue**, **Void**       |
| `partially_paid` | **Paid**, **Overdue**, **Void**                           |
| `paid`           | _(no transition card shown)_                              |
| `overdue`        | **Partially Paid**, **Paid**, **Void**                    |
| `void`           | _(no transition card shown)_                              |

Button labels are generated by `formatStatus(status)` which replaces underscores with spaces and title-cases each word. Exact rendered labels per status value:

| status value    | Button label       |
|-----------------|--------------------|
| `sent`          | **Sent**           |
| `viewed`        | **Viewed**         |
| `partially_paid`| **Partially Paid** |
| `paid`          | **Paid**           |
| `overdue`       | **Overdue**        |
| `void`          | **Void**           |

## Steps (General)

1. In the left sidebar under **Financial**, click **Invoices**. The browser navigates to `/invoices`.
2. In the table, click the **View** icon button (tooltip **"View"**) for the target invoice, or directly navigate to `/invoices/{id}`.
3. On the detail page, locate the card that appears immediately below the page header (present only when transitions are available). The card contains the label **"Transition to:"** followed by one or more small primary buttons.
4. Click the desired transition button (e.g., **Sent**). While the API call is in flight all transition buttons show a loading spinner (`updateStatus.isPending`).
5. On success the page data refreshes. The **Status** field in the **Invoice Information** card updates to the new status, the status Tag color changes accordingly, and the transition card updates to reflect the new set of available transitions.

## Transition Walkthrough — Draft to Void

1. Open an invoice in **Draft** status.
2. The transition card shows buttons: **Sent** | **Void**.
3. Click **Void**.
4. The invoice status changes to **Void**. The transition card disappears (no further transitions available from Void).

## Transition Walkthrough — Draft to Paid (full happy path)

1. Open invoice in **Draft** — transition card shows **Sent** | **Void**.
2. Click **Sent** — status becomes **Sent**; transition card shows **Viewed** | **Void**.
3. Click **Viewed** — status becomes **Viewed**; transition card shows **Partially Paid** | **Paid** | **Overdue** | **Void**.
4. Click **Paid** — status becomes **Paid**; transition card disappears.

## Notes
- Transitions are enforced client-side by the `statusTransitions` map in `InvoiceDetailPage.tsx`. Server-side enforcement is independent.
- `updateStatus.mutateAsync({ id: invoice.id, status: newStatus })` is called via `useUpdateInvoiceStatus` hook.
- There is no confirmation dialog before executing a status transition.
